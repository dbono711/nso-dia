# House conventions (learned from the user's l3vpn and l2vpn-eline packages)

These are the user's own conventions. Use them as the **default** for new packages and **always** when editing a package that already follows them. When a convention conflicts with the best-practice rules in the other reference files, best practice wins. The known conflicts are listed at the bottom; don't copy those patterns even though the reference packages contain them.

## Repository layout

The git repo wraps the package; the package is a subdirectory named after the service:

```
nso-<pkg>/                      # repo root
├── <pkg>/                      # the NSO package (what gets tarred and loaded)
│   ├── package-meta-data.xml
│   ├── src/{Makefile, yang/<pkg>.yang}
│   ├── python/<pkg_underscored>/
│   │   ├── __init__.py
│   │   ├── main.py             # thin: callbacks + Main app only
│   │   ├── context.py          # ServiceContext dataclass
│   │   ├── <pkg_underscored>.py   # service class with configure()
│   │   ├── device.py           # Device helper (NED id, platform lookups)
│   │   ├── network.py          # Network helper (interface parsing, IP math, validation)
│   │   ├── premod.py           # PreMod: fills hidden/derived leaves before create
│   │   └── completion.py       # CLI completion actionpoint for interface names
│   └── templates/<pkg>-<feature>.xml   # one template per feature
├── tests/                      # pytest integration tests against a live NSO via MAAPI
│   ├── conftest.py
│   ├── test_service.py
│   └── requirements.txt        # pinned pytest
├── Makefile                    # build-package / clean-package / test-package
├── README.md
├── CHANGELOG.md                # generated by release-please; never hand-edit
├── .release-please-config.json
├── .github/workflows/{release-please.yml, package-artifact.yml}
├── pyrightconfig.json          # extraPaths -> $NCS_DIR/src/ncs/pyapi
└── .gitignore
```

The Python package dir is the package name with `-` → `_` (`l2vpn-eline` → `l2vpn_eline`). Only include `premod.py` and `completion.py` when the service needs them, but default to including `completion.py` whenever the model has a device-interface leaf.

## YANG

- `namespace "http://dbono711/<pkg>"`, `prefix <pkg>`, `yang-version 1.1`.
- Include `organization` and `contact` blocks; copy them verbatim from an existing package in the workspace if one is available, otherwise ask or leave a `TODO`.
- Revisions newest first, each with a one-line description of the change. Add a new one on every model change.
- Services live under `augment /ncs:services { list <pkg> { ... } }`.
- Keys are `"customer-name service-id"`: `customer-name` is a leafref to `/ncs:customers/ncs:customer/ncs:id`, `service-id` is a string with `tailf:cli-allow-range`.
- `tailf:info` on every list, container and leaf.
- Device structure: `container provider-edge { list device { key name; leaf name { leafref to /ncs:devices/ncs:device/ncs:name; must "contains(.../ncs:device-type/ncs:cli/ncs:ned-id, 'cisco-iosxr-cli') or ..." { error-message ...; } } list interface { key name; ... } } }`. That `must` restricts which NEDs a device can use — extend it when adding NED support.
- Interface parameters go in a `grouping interface` (`cir`, `mtu`, `port-mode` boolean mandatory, `vlan-id` with `when "../port-mode = 'false'"`, ...).
- `vlan-id` shape depends on the service layer:
  - **L2 services (l2vpn-eline):** a `leaf-list` with `min-elements 1`. One EFP/sub-interface can carry several VLANs, and the hidden `efp-id` from premod is the sub-interface number.
  - **L3 services (dia, l3vpn-style):** a single `leaf` with `mandatory true`, because each sub-interface carries exactly one IP. Use the VLAN id as the sub-interface number (`Ethernet0/3.100`), so there's no `efp-id` and no premod. Several VLANs on one port means several `interface` entries or instances, not a leaf-list.
- Values the service computes rather than the operator enters (e.g., sub-interface `efp-id`) are leaves hidden with `tailf:display-when "false()"` and filled in `premod.py`.
- Interface-name leaves get `tailf:cli-completion-actionpoint <pkg-short>-interface-name { tailf:cli-completion-id "provideredge-"; }`, backed by `completion.py`. In `cb_completion`, `kp.dup_len(n)` keeps the first `n` keypath elements, and `n` must land on the device list entry. Count one element per node **and** one per key set. For `/ncs:services/<pkg>:<pkg>{c s}/provider-edge/device{d}` that's `services`, `<pkg>`, `{c s}`, `provider-edge`, `device`, `{d}` = **6**. Recount whenever the model shape above the device list changes, then `cd(root, str(kp.dup_len(n))).name` gives the device.
- Optional sub-features are `presence` containers (`ce-routing`, `static`, `bgp`).
- Passwords: `tailf:aes-cfb-128-encrypted-string` with `tailf:suppress-echo true`.
- IDs that must be unique network-wide (VPN id) come from **resource-manager** (`<required-package>resource-manager</required-package>`), with an optional operator-supplied leaf used as the requested id.

## Python

- `main.py` is thin. `cb_pre_modification` returns early on delete (`op == 2`), builds a `ServiceContext` and calls `PreMod(ctx).fill()`. `cb_create` builds a `ServiceContext` and calls `<Service>(ctx).configure()`. `Main.setup` registers the servicepoint and the completion action.
- `context.py`:
  ```python
  @dataclass(frozen=True)
  class ServiceContext:
      log: Any
      root: Any
      service: Any
  ```
- The service class takes `ctx`, builds `Network(ctx)` and `Device(ctx)` helpers, and exposes `configure()`. Big services split into `_setup_<feature>()` methods, each applying its own template.
- NED branching uses substring checks on the NED id from `ncs.application.get_ned_id(device)`: `"cisco-iosxr" in ned` is checked **before** `"cisco-ios" in ned` (the IOS string is a prefix of the XR one).
- Interface names are split into type and id with `get_intf_type_and_id()`, and CIDR into address + mask with `get_ip_and_mask()` (via `ipaddress`). Pure helpers that don't touch CDB are **module-level functions in `network.py`**, not `Network` methods and not a separate `utils.py`, so they can be unit-tested without NSO. Methods on `Network` are for things that read `self.ctx.root` (device config lookups, validations).
- Shared device config the service doesn't own (an IGP process, a VRF, a parent interface's mode) is **validated in Python** with a clear `ValueError` telling the operator what to configure. The template also guards it with `tags="nocreate"` on the shared parent (e.g., `<isis tags="nocreate">`), so a missed validation can't make the service create it. Use `tags="merge"` on the child the service does own.
- "Already in use" validations (interface has an IP, sub-interface exists) can read device config directly in `cb_create`. FASTMAP removes the service's own previous output before create runs, so re-deploys and updates don't trip on the service's own config. The lifecycle test's `check_sync()` assert proves it.
- Type hints on every method, Google-style docstrings (`Args:` / `Returns:` / `Raises:`), f-strings for log messages.
- Unit conversions that differ per NED stay in Python (e.g., CIR × 1,000,000 for IOS, Mbps for XR).

## Templates

- One template per feature: `<pkg>-vrf.xml`, `<pkg>-intf.xml`, `<pkg>-bgp.xml`, `<pkg>-policy.xml`, ... For small services, a single `<pkg>-template.xml` is fine.
- Device name from `{$DEVICE-NAME}`. Variables are UPPER-KEBAB-CASE (`$INTERFACE-TYPE`, `$IPV4-LOCAL-MASK`).
- Each NED gets its own commented namespace block (`<!-- ios-xr interface configuration -->`).
- Branching uses `when="{...}"` attributes on elements (`<GigabitEthernet when="{$INTERFACE-TYPE = 'GigabitEthernet' and $PORT-MODE = 'true'}">`) rather than `<?if?>` processing instructions.
- Python initializes every optional variable to `""` and applies the template once, then re-applies it once per value of a multi-valued input (`for vlan_id in intf.vlan_id.as_list(): vars.add("VLAN-ID", vlan_id); template.apply(...)`).
- Optional leaves left unset are guarded with `when="{$MTU != 'None'}"`. A Python `None` becomes the string `'None'`.
- Device descriptions are `NSO:{$CUSTOMER-NAME}:{$SERVICE-ID}`.
- Policy-map and xconnect names reuse `{$SERVICE-ID}`; pseudowire and VC ids reuse `{$VPN-ID}`.

## Build, test, release

- Root `Makefile` uses `.ONESHELL:` and `.SILENT:`. Its targets are `build-package` (`$(MAKE) -s -C <pkg>/src all`), `clean-package`, and `test-package` (creates `tests/.venv`, installs requirements, runs `pytest tests/ -v`, deletes the venv, exits with pytest's code), plus `all`, `clean` and `test` aliases.
- `src/Makefile` is the `ncs-make-package` one with `$(DIRS)` mkdir. Add NED YANG to `YANGPATH` only when the service YANG actually imports NED modules.
- `tests/conftest.py` provides a session-scoped `maapi` fixture (`ncs.maapi.Maapi()` + `Session(m, 'admin', 'python')`) and an autouse `test_customer` fixture that creates `pytest-customer` under `/customers` and removes it at teardown.
- `tests/test_service.py` does a full lifecycle: create the instance with maagic, `t.apply()`, read and assert in a `try`, delete in `finally`, then verify the delete. Instance names start with `pytest-`, and devices are netsim names like `ios-0` / `iosxr-0`. The user's netsims carry real lab config, so inspect them before choosing test interfaces (see `testing.md`). Validations are tested with in-transaction negative tests, and shared prerequisites come from create-only-if-missing fixtures (same file).
- Conventional Commits (`feat:`, `fix:`, `feat!:` / `BREAKING CHANGE:`) drive release-please, which bumps the version and writes `CHANGELOG.md`. Keep `package-version` in `package-meta-data.xml` in step with the release (bump it in the same change, matching the semver level of the commit type).
- `package-artifact.yml` tars the **contents** of `<pkg>/`, so `package-meta-data.xml` sits at the top level of the tarball, and attaches it with its sha256 to the GitHub release.
- `.gitignore` covers `load-dir`, `*.fxs`, `.venv`, `logs`, `*gz`, `.pytest_cache`, `graphify-out/`.

## Where best practice overrides the reference packages

The reference packages contain these patterns. Don't reproduce them; write the corrected form instead, and point them out when editing a file that contains them (without silently rewriting unrelated code):

| Seen in reference | Write instead | Why |
|---|---|---|
| `cd(root, f"/ncs:devices/ncs:device/{name}")` | `root.devices.device[name]` (or keypath `/ncs:devices/device{<name>}`) | `/device/<name>` isn't valid keypath syntax for a list entry; it only works by accident or not at all |
| `raise Exception(...)` | `raise ValueError(...)`, or a small package-specific exception | Callers can tell validation failures apart from bugs; the message still reaches the operator |
| camelCase parameters (`deviceName`) | snake_case (`device_name`) | PEP 8; mixed styles in one file read badly |
| `"""Docstring Missing."""` placeholders | a real one-line docstring | Placeholders are worse than none |
| Dead methods referencing attributes that don't exist (`self.service`, `self.root` in `get_ipv4_peer_loopback`) | delete them, or fix them to use `self.ctx` | Breaks on first call |
| Writing an allocated value back into a service **config** leaf from `cb_create` (`service.vpn_id = vpn_id`) | store it in a `config false` + `tailf:cdb-oper` leaf (e.g., `allocated-vpn-id`), or set it in pre-modification | Changing the service's own inputs inside create fights FASTMAP: the write is part of the reverse diff and makes re-deploys noisy |
| `list(set(range(...)) - set(used))[0]` for next free id | `min(set(range(...)) - set(used))`, raising if empty | Deterministic, and fails cleanly when exhausted |
| `ncs-min-version 5.5` | `6.0` or higher (house current: `6.4`) | Target is NSO 6.x |
| Unused imports (`ietf-routing-types` with no `rt-types:` usage) | drop them | Noise, and an extra compile dependency |
| A NED-version-specific `YANGPATH` in `src/Makefile` when the YANG imports no NED module | omit it | Breaks the build on any machine with a different NED version |
| Template-time XPath reaching into the service by Python-known keys (`{/provider-edge/device[name=$DEVICE-NAME]/interface[name=$INTERFACE-NAME]/efp-id}`) | pass it as a variable (`$EFP-ID`) from Python | Shorter, easier to test, and no hidden coupling between the template and the model shape |
| Lifecycle tests that only check CDB existence | also assert on `commit dry-run` output for a device | The README promises device-config validation; the tests should deliver it |
